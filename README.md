# WeDownload

家庭服务器上的下载管理应用。把链接丢给它，让 N150 7×24 挂着下载；手机上直接看进度、在线播放、翻漫画、解压文件。

- 入口：**https://wedownload.sherlockguo.com**
- 引擎：aria2 1.37.0（HTTP / HTTPS / FTP / SFTP，16 线程，断点续传）
- 前端：自建 mobile-first 页面（深色/浅色），AriaNg 保留在 `/ariang/`

---

## 怎么用

### 加下载

1. 打开 https://wedownload.sherlockguo.com
2. 点右下角 **+**
3. 粘贴下载链接，一行一个，可以一次粘多条
4. 点 **开始下载**
5. 在「任务」页看实时速度和进度；完成后进「已完成」

任务卡片右侧可以暂停、继续、删除（删除任务不会删文件）。

### 看文件

底部切到「文件」，就是服务器 `~/downloads/` 的目录树：

| 文件类型 | 点开是什么 |
|---------|-----------|
| 视频（mp4/mkv/webm/mov） | 全屏播放器，可拖动进度、全屏 |
| 音频（mp3/m4a/flac） | 全屏播放器 |
| 图片 | 大图预览；同目录有 2 张以上图片时出现「开始阅读」，进入左右滑动的漫画阅读器 |
| 压缩包（zip/rar/7z） | 弹框输入密码 → 解压到同名目录 → 自动进入 |
| PDF | 新标签页打开，用浏览器自带阅读器 |
| 纯文本（txt/md/srt） | 页内预览 |
| 其他 | 直接下载到当前设备 |

每行右侧的 ✕ 可以删除文件（会二次确认，不可恢复）。

### 其他

- 右上角显示当前总速度；底部「主题」切换深色/浅色（会记住）
- 解压密码在同一次会话内会记住，重复解压同个包不用重输

## 它能接手什么样的链接

关键是 **直链**：在浏览器地址栏打开就会直接开始下载文件的那种 URL。

| 类型 | 支持 | 说明 |
|------|------|------|
| 镜像站文件地址 | 可以 | 清华 TUNA、阿里云、腾讯云等，实测 4~5 MB/s |
| 软件官网安装包直链 | 可以 | 直接指向 `.dmg` / `.exe` / `.zip` 的 URL |
| 网盘离线下载产出的直链 | 可以 | 先把资源转存到网盘，再取它的下载直链 |
| FTP / SFTP 地址 | 可以 | aria2 原生支持 |
| 网页地址（视频页、网盘分享页） | 不行 | 只会把 HTML 存成一个文件 |
| 磁力链 / `.torrent` | 不行 | N150 在移动 CGNAT 后，拿不到 peer，实测速度为 0 |

**判断是不是直链**：把链接粘到浏览器地址栏回车。直接弹出下载框、或页面变成播放器/纯文本内容，就是直链；如果打开的是一个有导航栏和按钮的网页，就不是。

## 已知限制

1. **BT 不可用**：中国移动 CGNAT，没有公网 IP，无法获取 peer。已从 qBittorrent 全面切换到 HTTP 直链。
2. **单人使用**：没有登录和权限系统，靠 Cloudflare Tunnel 隐藏真实 IP。域名本身不要外传。
3. **不支持网页抓取**：给网页地址不会自动解析出视频，只下载 HTML。需要先自己拿到真实文件直链。
4. **大文件在手机上是边下边播**：视频通过 Range 请求流式读取，弱网拖动会略卡。

## 常见问题

| 现象 | 原因 / 处理 |
|------|------------|
| 顶部显示「无法连接下载引擎」 | 服务器上 `aria2` 没跑，等 deploy-agent 的 cron 自愈或看日志 |
| 任务一直 0 B/s | 链接多半不是直链，或源站需要登录态 / Referer |
| 下回来是一个 `.html` 文件 | 加的是网页地址，不是文件直链 |
| 视频点了没反应 / 一直转圈 | 浏览器不支持该编码（如 H.265 的 mkv），换 mp4/H.264 |
| 解压报「密码错误」 | 密码不对，或压缩包本身损坏 |
| 添加任务报 `could not be retrieved` | 链接失效，或源站拒绝服务器 IP |

## 技术构成

```
浏览器 (手机/电脑)
      │ HTTPS
      ▼
Cloudflare CDN ── cloudflared 出站隧道 ──▶ N150
                                            │
                                  127.0.0.1:8080  Node 服务 (server/index.js)
                                    ├─ /            自建前端 (public/)
                                    ├─ /api/*       任务 / 文件 / 解压
                                    ├─ /jsonrpc     → aria2 RPC
                                    └─ /ariang/     旧界面（备用）
                                            │
                                      aria2（下载引擎，127.0.0.1:6800）
                                            │
                                      ~/downloads/
```

| 组件 | 说明 |
|------|------|
| `wedownload.service` | Node 20 服务，零运行时依赖（不装 npm 包），监听 8080 |
| `aria2.service` | 下载引擎，配置在 `config/aria2.conf` |
| `cloudflared` | Cloudflare Tunnel，`wedownload.sherlockguo.com` → `localhost:8080` |
| WeMonitor | 部署状态 + TCP 8080 健康检查 |

设计上刻意不引入 Express 等依赖：部署时只需 `git` 产物解包 + 重启服务，不需要在 N150 上跑 `npm install`。

安全上，所有文件路径都经 `realpath` 校验并锁定在 `~/downloads/` 内，`../` 穿越和指向外部的符号链接都会被拒绝。

## 部署与运维

改动 push 到 `master` 即自动发布：

```
push → GitHub Actions（打包 config/scripts/server/public → tar.gz → Release/R2）→ webhook → deploy-agent.sh → scripts/restart-n150.sh
```

`restart-n150.sh` 负责：

1. 复制 aria2 配置到 `~/.aria2/`
2. 按需补装 `p7zip-full`
3. 写入并重启 `wedownload.service`
4. 停用旧的 Python 代理（`ariang.service`）
5. 健康检查：新服务起不来时自动回退到旧代理，避免整站不可用

服务异常由 N150 上的 deploy-agent cron 每分钟健康检查自动恢复，**不要手动重启**。
